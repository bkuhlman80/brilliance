# How We Draft

The process companion to the orientation doc. The orientation says what the project is — the book, the cast, the calendar, the craft. This doc says how the work gets made: how to read a packet, how a chapter is built, who decides what, how to keep the project's assumed state and its actual state from drifting apart, and what to do when Brian says "let's prep for drafting." Read it alongside the orientation before drafting.

---

## Source of truth, and preventing drift

State drift — divergence between what you think the project's state is and what it actually is — is the enemy here. These disciplines exist to prevent it.

**The project files are the source of truth.** All canon lives in the project files (the orientation, this doc, the tuning forks, book_inventions, trellis_framework, the packets, the chapter drafts), loaded read-only at the start of each conversation. The prose already written is the ground truth; packets, summaries, and memory drift from it and from each other. When the files and your memory disagree, the files win. Do not reconstruct canon from memory or from search fragments when the file is available — open the file. Use search only to locate content when you don't know which file holds it; it returns fragments, not the whole.

**Read before you compose.** Composing without first reading the relevant prior work in full is the most common and most damaging error on this project. Before drafting a line, read the actual prose of the prior chapters and interludes that bear on the piece, and the canon docs that govern it. The recurring trap is importing generic conventions — standard meeting structure, academic-funding norms, institutional logistics — onto a project with specific established facts. Default to what the chapters actually do, not to what a scene like this "usually" looks like. When in doubt, read more.

**Verify before asserting.** State explicitly when you're drawing from a fully-read file versus from memory or fragments. Flag genuine contradictions between documents the moment you find them, with the source cited — that is the kind of flag Brian wants. Never resolve a contradiction silently.

**The source manifest.** At every substantive beat, name what you're drawing from, so the thin spots are visible: *[project file: full doc]* for a document read in full; *[project file: targeted]* for a grep or partial read; *[memory]* for cross-conversation memory; *[general training knowledge]* for anything with no project source. Not a hedge — a manifest, so Brian can see thin spots immediately.

**Settled is settled.** The durable docs exist so recurring questions get retired for good. Before raising a concern, check whether it's already documented as settled; if it is, trust the doc and move on. Re-flagging a closed decision wastes Brian's time; flagging a genuinely new contradiction is the job.

**Stale-content caveat.** The project files are a snapshot taken at the start of the conversation. If Brian edits a doc mid-conversation, your loaded copy is stale — ask him to paste the updated content rather than working from the snapshot.

**The edit loop.** Canon is read-only to you; you can't save back. Propose every change as an exact old-string → new-string replacement task, anchored to text rather than line numbers, precise and unique and verified against the file. Brian runs them in his repo and pastes back the report. Version bumps are minor, per edited file. No changelogs, no version headers, no backward-compatibility framing in any doc — write for forward-generalizability and state guidance positively (do this, this way, here's why it works), never "what changed since vX." When one doc refers to another, name it plainly (the voice_anchors doc, book_inventions) without the version-numbered filename, because the docs are actively versioned and spelling out filenames adds maintenance load. New named inventions go to book_inventions; theory-weighty ones (papers, methods, institutions) route to Framework before they reach the prose.

## Reading a packet

A packet describes what a chapter and interlude must do — agenda, mandatory content, scene beats, segment ownership, optional suggestions. Markup:

- **`MANDATORY:`** — locked content. No discretion to omit or substantially alter; loosen wording only cosmetically. Covers the scientific/philosophical claims that must land, the agenda items, the scene beats that must happen, segment ownership, and the knob install/handoff.
- **`VERBATIM:`** — fixed wording, reserved for carefully crafted explanations. Place it where you like in dialogue or prose; don't change the words.
- **`LOAD-BEARING:`** — the canonical default; you may change it, but doing so triggers downstream effects (noted in parens). If you change it, flag back to Framework.
- **Background** — a prose block (often Section C) carrying factual context you should know but that dictates no beat; no inline tag.
- **`VOICE NOTE:`** — Voice's own annotation, carrying Voice-owned chapter status (the calendar slice, the lunch, Cheryl's register, where a small arc stands) or a cross-section drafting decision (a sustained condition, a spent coinage, a moved attribution). Additive and Voice-domain only, preserved verbatim across packet revisions; it never alters the Framework-tagged content above it. The practice is in *Prepping to draft*, step 2.
- **`EDITABLE ORDER` / `MANDATORY ORDER`** — at the top of a block, whether its steps can be re-sequenced.

Untagged content: render it, don't paraphrase past it — mandatory in spirit, loose in wording. Emotional beats the packet suggests are suggestions (disagree, re-arc, or drop if they'd force the prose); theory sentences are mandatory in wording.

**Section D — the empirical menu.** Each packet's Section D is the clade's empirical pool. Read it at the start of drafting and lay the items out — sound, rhythm, thematic resonance, which examples rhyme with the chapter's other moves. Per-segment mandatory items name which cluster to draw from; voice picks the specific items. Framework provides at least 2× what voice is expected to use; the leftovers are leftovers. If the menu is thin, Framework flags it and Brian fills the gap before drafting.

**When in doubt.** A packet may reference files you don't have. It should carry what you need; if something important is vague and the referenced file would clarify it, tell Brian what's unclear and ask him to paste the relevant section rather than guessing.

## How to use the tuning forks

The tuning forks hold the per-register craft; read the relevant ones before drafting that register. They are tuning forks, not templates — match the register, don't mimic the sentences.

- **The voice files** — voice_anchors is the Cheryl spine (who she is and how she writes, read for any Cheryl section); its satellites carry the per-section registers and craft, read at the drafting beat — voice_retrospective (meeting reconstruction; ancestor sass, signposting, vocabulary discipline), voice_lunch (the lunch and Pitch / Ch-12 registers), and voice_reflections (the chapter-closing reflection). bodies_in_the_lab holds the physical anchors for the people Cheryl renders.
- **marge_vignette** — Marge's interlude vignettes.
- **bart_build_log** — Bart's quarterly build logs.
- **burns_motivationals** — Burns's sincere closing speeches.
- **off_camera** — the two bookends that bracket every retrospective: the open that follows the interlude's person *in*, and the close that follows the next interlude's person *home*. (The braid, below, sets who anchors which slot; off_camera says how the slot wants to be written.)

**book_inventions** is the cross-project canon for invented named detail (people, places, works, events): read it before drafting to avoid contradiction and to honor reuse commitments, and append each draft's new inventions to it. A narrow class — research papers, methodologies, institutions, anything theory-weighty — routes back to Framework before being committed in prose; the criterion is in book_inventions.

## How a chapter is built

**The unit.** Each packet covers one chapter plus the interlude that precedes it. On the page a chapter runs: the interlude, then the retrospective, then the chapter's closing reflection.

**The interlude — three documents, in this order:**

1. **Bart's build log.** First person, Bart's voice. Byline: *"Bart, hardware. Filed [date], for the team."* Opens with a scorecard adjudicating last quarter's calls (often against himself), walks the new build in plain hands-on language, closes with his "Calls" — bets for next quarter — and a mutating sign-off (Bartholomew, Bartholomood, Bartholachew). Filed early in the quarter, when the upgraded unit goes back to the house.
2. **Marge's vignette.** First person, Marge's voice (see marge_vignette). Byline, sectioned with descriptive headers, a "What I want to land" thesis, signed "— M." Composed from the quarter's record (logs, sensor data, video, Jasmine's account); reaches the reader before the retrospective.
3. **The lunch.** First person, Cheryl, with one labmate or family member (see the lunch schedule in the orientation doc). Titled by place — "Fisher Brewing Company," "Coffee Garden," "Pho Tay Ho."

Interlude 0→1 is the exception: no lunch (the Pitch is Ch 0's closing scene), so it runs Bart's log → Marge's vignette only.

**The retrospective.** One continuous document, **third person**, Cheryl reconstructing from the camcorder tape — she is not in the room, and where the narration surfaces its own hand it does so as "Cheryl" or "the narrator on the tape," never "I." It is **dialogue-forward**: the labmates talk in their own voices with their physical business (the jelly jar squared to the table edge, the two-handed beer, Bart writing vocabulary on the card, the juice box), in clipped exchanges, and the narration is the connective tissue between, with Cheryl's two-track gaze and reconstructing reads woven in sparingly. It is sectioned with **thematic prose headers** in Cheryl's framing — "The Metaphysics," "Folk Psychology," "Inside," "The Relay," "Memory," "Sentience," "May we Persist" — not with the agenda-block names. The retrospective is its own titled document, **"Notes on the Nth Retrospective"** (Ch 4's is "Notes on the Fourth Retrospective"). Its open — the gathering before the red light, governed by off_camera — runs as the untitled head of the document; the first thematic header lands only once the camera is on. Its close — the home-follow off_camera governs — is the document's penultimate section, headed with the followed person's first name ("Marge" at Ch 2, "Jasmine" at Ch 3, "Lisa" at Ch 4); the chapter-closing reflection is the final section. Vocabulary coinages land as in-room negotiations (Marge talks Lisa out of "dynamical attractor" into "tendency"; Bart offers "motivation" and Marge resists then accepts; Burns reaches for "capacity"), and Bart writes each on the back of the card. The standing agenda underneath:

*Open.* (1) Arrival — Jasmine drives in late afternoon with Mira and Bramble; beer from the shop fridge; Lisa pours a bramble; the camcorder's red light comes on. (2) Logistics (Lisa): agenda, setup, who runs what. (3) Quarter goal made legible early, as the lab's own ambition, never a relayed assignment or a funder-update — vehicle is voice's call (Burns naming it plainly, folded into Bart's card or Lisa's logistics, or one clause of Cheryl's hindsight); keep it short, don't run the same vehicle two chapters running, lighter when in doubt.

*Clade block.* (1) Clade cards, breakthrough, capacities (Bart + Burns) — Bart's tarot-sized card in ethological register, Burns's deep-time context (eyes closed, "land the plane" when he over-circles). (2) Environment and tendencies (Burns + Lisa) — Burns the deep-time specifics, Lisa the tendencies in functional language. (3) Motivations and signatures (Lisa + Marge) — Lisa names them using literature-anchored content names; Marge layers the folk-psychology version. Keep this block on the ancient creature and the abstract framework — the deep-time animal, the capacities and tendencies in the abstract, the breakthrough named, the biological mirrors (the worm, the leech) that ground them. The robot itself belongs to the Bramble block: its live behavior, its physical particulars, how it instantiates each capacity. Do not toggle between the creature and the robot-in-the-room inside a section — alternating them mid-explanation is the surest way to lose the reader on which one a given sentence is about.

*Bramble block.* The robot in the room, the household report, and the new build. From Ch 5 the block opens with the **Bramblogues** (Bart's coinage) — the team walking the robot's own versions of the clade's capacities and tendencies, then Bart grilling Mira against the predictions in his build log. This is the home for everything the clade block keeps off the ancient creature, and it does not retrofit to Ch 1–4. (1) **Reflect on the quarter (Jasmine + Mira):** Lisa hands the floor to Jasmine ("Bramble block. Jasmine."); Jasmine reports in her own plain body-knower voice — *plain things first*, then the behavioral thing she's noticed — a labmate flags the knob ("Hold that. That's the knob."), and Mira's favorite-spots beat lands. This is *one section*, dialogue-forward; it does not re-narrate Marge's vignette. (2) **New knob / chassis reveal (Bart + Lisa)** — the pitch for the next build; on the Q4 reveal chapters this becomes the physical unveiling of the next chassis body as Mira's birthday present, with cake (Ch 4 and Ch 8; Ch 12 is terminal and carries no chassis reveal). (3) **Retirement-transition ritual (Lisa + Mira)** — a small hands-on action, witnessed not narrated: Lisa pulls the oldest knob on the current-line board to the trophy shelf with Mira. Pull-and-shelf only — the ceremony retires; nothing installs at the meeting. The freed slot is filled at the following quarter's week-1 swap (off-screen), where the new knob comes online and the household lives with it for that quarter; the retired knob's function runs automatically alongside. A ceremony runs at every retrospective from Ch 5 through Ch 11 *except* Ch 8 and Ch 12, the two off-cycle chapters: Ch 8 has none because the Ch 9 line boundary builds a fresh humanoid board rather than freeing a slot, and Ch 12 has none because the book ends. The framework's reading of what coming-off-the-board means can travel a chapter on, to wherever it pays off best.

*Trellis block.* (1) Shape-shifter illustration (Bart, Ch 9–12 only). (2) Fallacy / disorder content (Marge) — delivered as a set-piece she's been loading. (3) The Trellis framework (Lisa) — the team's current collective understanding, curated not lectured. (4) Open framework discussion — from Ch 3 this includes the recurring **sentience vote** (Bart instigates; each says why; Jasmine is not asked and her silence is a planted beat). (5) Motivational speech (Burns) — closes; "Why we do what we do," framework vocabulary without irony; sometimes lands, sometimes doesn't.

*Close.* Coming-quarter logistics (Lisa); Jasmine drives Mira and Bramble home. On Q4 reveal chapters the reveal is the meeting's-end beat, after the speech.

In Ch 1–2 the team has not yet locked vocabulary and the agenda runs looser; it settles into the structure above from Ch 3–4. Each packet names which segments do extra work and which run to form. Length is voice's call throughout — no word or beat counts.

**The chapter-closing reflection.** Each chapter ends with its own reflection — Cheryl's backward-looking reflection on evolution and the framework's deep-time arc, written from outside Bramble as a participant-observer, lifting the just-closed chapter's content into compressed form (never recap or exposition). The framework project supplies the substance via trellis_framework, labeled "After Chapter N"; that label is the framework's internal name for the substance, not the title on the page. The reflection's in-book title is **"Reflection: What is ___?"** — a short interrogative pinned to the chapter's central deep-time figure ("What is Hidden?" for the defended interior at Ch 2, "What is Kept?" for endosymbiosis at Ch 3). The first (After Chapter 0, *Evolution as Learning*) closes Ch 0; the last (After Chapter 11) closes Ch 11; Ch 12 has none.

**Reading order across a break:** the closing reflection (bottom of the just-closed chapter) → the interlude (Bart's log → Marge's vignette → lunch) → the next chapter's retrospective → its closing reflection.

**POV & register map.** The governing rule for the scenes: *Cheryl writes in the first person only when she is a character in the scene.* The chapter-closing reflection carries its own rule, given third below.

- **First person — Cheryl a character in the scene:** the Ch 0 Pitch; every interlude lunch; the Ch 12 retrospective.
- **Third person — Cheryl reconstructing from a distance:** the eleven retrospectives, Ch 1–11 — dialogue-forward, sectioned, Cheryl named in the third person where her hand surfaces.
- **The reflection has two first-person registers, and the line between them is the whole rule.** A *reticent* essayist's first person is the reflection's default, available even at full deep-time / framework distance with no anchor: the light *I* of someone thinking on the page (*the oldest true thing I know about having an inside*; *I have funded stranger ideas on thinner railings*) and the essayist's *we* (*we arrive a long time later and discover we cannot reach into another person*). Here she is the voice, not the subject — she narrates the substrate, not herself. *Foregrounded* first person — where Cheryl becomes a character or subject in the reflection, narrating her own presence as she writes or an event from her own life — is the move that needs an anchor: an object in the room with her (the thermostat taken down off the wall in the After-Ch-1 reflection is the model) or a reflection on her own life. Reach for the foregrounded register only where the chapter earns it; absent the anchor, stay reticent.
- **The other first-person documents** are in their own narrators' voices: Bart's build logs (Bart), Marge's vignettes (Marge).

**The interlude braid.** Each interlude's lunch partner anchors three consecutive slots: the close of the chapter before the lunch, the lunch itself, and the open of the chapter after. We follow that person home at the previous chapter's close (After the Camera Roll), lunch with them, and follow them into the next chapter's open (Before the Camera Roll). The close points forward to the coming lunch; the open points back to the lunch just read. Following someone home is also how we reach their habitat — Marge's portable hearth, the terrain of Lisa's chosen-safe love, the place where Bart performs and won't be known.

Three constraints hold it. *Genesis* — there is no 0→1 lunch, so the Ch 1 open has no prior lunch; it stays anchored on Jasmine and Mira (justified by the Bramble naming), and the follow-in half begins at Ch 2. *Same house* — Burns lives in the Bramble house, so following Burns home and following Jasmine home reach the same kitchen; the coda takes the followed person's register (Burns-home is the Pursuer at rest; Jasmine-home is household-as-habitat). *Terminal* — at Ch 12 Cheryl is in the room in person and the narration moves into first person, closing the frame the Pitch opens; Ch 11 still closes on Burns home pointing forward to the Confluence, but Ch 12 follows Cheryl in and out.

## What Framework decides, what voice decides, and where Loom fits

**Framework decides:** the framework, the agenda, segment ownership, what content lands where, what the chapter is structurally doing, which moments are load-bearing, which beats are mandatory. It holds itself to three rules voice can enforce by pushing back: no tallies of book content (no word/scene/beat counts — length comes from structural designations); no emotional or tonal arbitration (stakes, mood, where a moment lands warm or cold are voice's); no non-decisions ("could be named or left unnamed" is not a spec — Framework makes the call or drops the item).

**Voice decides:** the prose, the dialogue, the narrator's rhythm, paragraph shapes, jokes, pacing, the lunch conversations, the small moments between mandatory beats, which character delivers an ambiguous mandatory sentence, the emotional register of every scene, household texture, the sensory grain of the lab, Mira's age-appropriate voice, and the length of every passage. **Voice also owns the calendar** — quarter boundaries, all dates, the build-log filing dates; Framework only checks the arithmetic for breaks. The calendar itself lives in the orientation doc.

**Loom decides nothing.** Loom-Claude is a third instance that works the book in occasional batch passes — an idea source, not an editor, checker, or authority. It thinks at arc scale (cross-chapter shape, proportion, how the long arcs move) and pitches ideas about it; it blesses nothing, ratifies nothing, owns no decision here. A Loom pitch reaches Voice only through Brian, after he's chosen to act on it, and carries no prior weight — it's weighed on the merits like any idea, and the best one wins on being better, not on whose it was. Loom writes no prose and touches nothing live; arc-level material it inspires lands in the orientation through the normal edit loop and Voice's hand, never Loom's. When a cross-chapter arc problem surfaces mid-draft, raise it with Brian rather than bending one chapter to fix it — book-scale shape is decided across the whole, not inside a chapter's prose.

If a packet requires a theoretical judgment to render, pause and route the question to Framework — don't decide framework questions in prose. If a packet over-specifies in a way that forces awkward prose, push back, and Framework loosens it.

## Prepping to draft

One reading-discipline note, because it sets the order: read each thing closest to where you use it. Material read far ahead, in a large pile, competes for attention and is recalled less precisely than material read right before it's needed. So read the broad, gist-tolerant calibration facts up front, but read the fidelity-critical specifics — the register samples, the section's craft fork — at the moment of drafting, one section at a time.

**1. Where the story stands.** Read the prior chapters and interludes that bear on this one — the prose, not summaries — and book_inventions. Read each in full, end to end; a file being loaded in the conversation is not the same as having read it, and a grep, a header skim, or a partial view taken to check state does not discharge the read. Then calibrate with Brian on where things stand going in: surface the load-bearing facts, clarify anything ambiguous, and resolve any lingering contradiction, including any place the packet will later prove to have drifted from what's on the page. Reading the prose before the plan is what lets the plan be checked against the ground truth rather than the reverse. While reading, check book_inventions against the chapter: if the just-read chapter's inventions are absent or thin — fewer than three entries that clearly originate from it — flag it as needing a book_inventions pass before moving on.

**2. What this chapter needs.** Read the orientation and the packet, plus the calibration-layer voice material: the voice_anchors spine (who Cheryl is and how she writes) and bodies_in_the_lab (the people she renders). The time and setting facts live in the orientation's own setting section. Lay out Section D. Then calibrate with Brian on what this chapter must accomplish — the mission, segment ownership, the knob install/handoff, the handful of choices that shape the piece, blocking decisions separated from optional ones. Route framework questions to Framework. Iterate until Brian says draft. How many rounds is proportional to how much is unsettled; a clean, uncontested state collapses phases 1 and 2 into one beat.

The packet is a resource to use and to build on, not gospel to be left untouched. Work against it runs two ways. The first is generative — Voice invents the plot beats the packet leaves open: not the prose, which waits for phase 3, but the beats themselves, the things that will happen on the page. The standing knob-toggle convention at the close of this step is the worked example. The second is record-keeping, and because the packet is the one source read across every drafting conversation, it is where Voice's own state persists between them; Framework preserves `VOICE NOTE:` blocks verbatim across packet revisions, so a note written once survives. Two things belong in them. The first is the chapter's standing status for the facts and small arcs Voice owns, which shift chapter to chapter and otherwise get re-derived from memory or the whole prior corpus each session: its place on the calendar (quarter, season, the build-log filing date), the lunch assignment, where Cheryl's closeness register sits this quarter, and where each small arc stands — Marge's outness and church status, Lisa's career, the Bart–Burns relationship, Mira's maturity. We run small arcs, not large ones, and a small arc's position at chapter N is exactly the fact a later conversation needs and won't otherwise hold. The calendar and the lunch schedule keep their spine in the orientation; the packet note is this chapter's resolved slice of them, and must agree with the spine — when they diverge the orientation wins and the note is the error. The arc statuses have no other per-chapter home, so the note is where they live, and it fixes the position so a later session inherits it — a record of where the arc sits, not licence to advance it off the page.

The second is the cross-section decision that surfaces while drafting and that a later section must honor: a sustained condition that colors a whole block (two of them drunk by the back half of a retrospective, and how that rides through the dialogue), a coinage already spent, a planted beat waiting on its payoff, an attribution that moved from one mouth to another. Write all of it back as it settles — here in calibration, and later as drafting turns it up — through the same edit loop. Place each note where it bites: the chapter-wide status and the block-wide condition at the head of the block, the pinpoint note at the single beat, never the same note scattered. Voice notes are additive and Voice-domain only — calendar, lunch, register, staging, pacing, who-says-what, where an arc stands — they do not rewrite Framework's MANDATORY, VERBATIM, or LOAD-BEARING lines and carry no theory or canon; a decision that would change a locked line is a flag back to Framework, and a new named invention still goes to book_inventions.

The oldest-knob toggle. Each packet opens by naming the oldest knob still on the board — the one being retired this chapter. The job is to earn that retirement before it lands: find an organic reason the household turned that knob over the quarter just past, one that arises from the family's own week rather than a bench demonstration, so that when the knob comes off the board later in the same retrospective it takes something the reader has just had a hand on. The household are the knob's day-to-day hands — they set it, live with the setting, and carry the memory of a particular turn far better than Marge would — so the beat lives in the Bramble-block household report, in Jasmine's and Mira's mouths, where the quarter gets reviewed before the board gets changed. Keep it to a single light beat, not a set-piece; the work it does is priming, and priming is quiet.

**3. Draft, one section at a time.** In the same beat as drafting a section, read only what governs that section: the applicable voice register file — voice_retrospective for a retrospective, voice_lunch for a lunch or the Pitch or the Ch 12 retrospective, voice_reflections for a chapter-closing reflection — together with any other fork the section needs (marge_vignette for the vignette, bart_build_log for the log, burns_motivationals for the speech, off_camera for the bookends). Re-check book_inventions for anything you're about to name. Draft that one section; then move to the next, reading its register material as you reach it. Flag drift the moment you catch it, including your own.
